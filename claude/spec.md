# 사이트 명세

## 형태

단일 페이지 세로 스크롤. 라우팅을 나누지 않는다.
가로형 슬라이드 형태는 만들지 않는다.

## 섹션 순서

1. Hero — 이름, 직군, 한 줄 소개, 링크(이력서 PDF / GitHub / Blog)
2. 문제 해결 — 케이스 5개. 이 사이트의 본체
3. 프로젝트 — 카드 3개
4. Contact — 이메일, GitHub, Blog

## 케이스 카드 구조 (5개 전부 동일, 예외 없음)

제목 → 그림 → 문제(3줄) → 해결(3줄) → 결과(3줄)

- 제목은 h2, 문제/해결/결과는 h3
- 그림은 figure + figcaption
- 각 3줄은 ol
- 카드 하단에 관련 저장소·문서 링크
- 5개 카드는 같은 컴포넌트에 데이터만 바꿔 렌더한다

## 케이스 목록 (제목은 확정, 본문은 내가 채운다)

1. AI 협업 개발 체계 — 명세·린트·스킬로 품질을 규칙으로 강제
2. 1:1 채팅 읽음 표시 21초 지연을 구독-재조회 왕복 제거로 0.8초로 단축
3. 측정을 두 번 틀린 끝에 병목이 DB가 아님을 규명하고 변경하지 않기로 판단
4. Redux Toolkit 스토어 설계로 FE 4인의 중복 API 호출을 전역 상태로 통합
5. 커서 초기화 분리로 무한 스크롤과 검색이 함께 동작하도록 해결
