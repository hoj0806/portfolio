# 사이트 명세

## 형태

단일 페이지 세로 스크롤. 라우팅을 나누지 않는다.
가로형 슬라이드 형태는 만들지 않는다.

## 섹션 순서

프로젝트가 상위 단위다. 케이스는 별도 섹션이 아니라 그 프로젝트 아래에 이어진다.

1. Hero — 이름, 직군, 한 줄 소개, 링크(이력서 PDF / GitHub / Blog)
2. 가지마켓 — 프로젝트 헤더 + 케이스 1~3
3. PokeCardFlip — 프로젝트 헤더 + 케이스 4
4. Planyang — 프로젝트 헤더 + 케이스 5~6
5. Contact — 이메일, GitHub, Blog

섹션 id는 프로젝트 id(`eggplant-market` / `poke-card-flip` / `planyang`)를 그대로 쓴다.
목차·스크롤스파이·앵커가 이 id를 공유한다.

## 프로젝트 헤더 (3개 전부 동일)

스크린샷 → 프로젝트명 → 한 줄 설명 → 기술 스택 → 링크(배포 / 저장소) → 체험 계정

- 프로젝트명은 h2
- 스크린샷은 본문 폭을 다 쓰고 비율은 16/10으로 고정한다. 세 프로젝트의 높이가 같다
- 체험 계정은 로그인이 필요한 서비스에만 붙는다
- "관련 케이스" 점프 링크는 두지 않는다. 케이스가 바로 아래에 이어진다

## 케이스 카드 구조 (6개 전부 동일, 예외 없음)

제목 → 그림 → 문제(3줄) → 해결(3줄) → 결과(3줄)

- 어느 프로젝트의 이야기인지는 적지 않는다. 그 프로젝트 섹션 안에 놓이므로 자명하다
- 제목은 h3, 문제/해결/결과는 h4
- 그림은 figure + figcaption
- 각 3줄은 ol
- 카드 하단에 관련 저장소·문서 링크
- 6개 카드는 같은 컴포넌트에 데이터만 바꿔 렌더한다

## 네비게이션

목차는 2단계다. 프로젝트가 상위, 그 프로젝트의 케이스 제목이 하위다.
목록은 `content/projects.ts`와 `content/cases.ts`에서 파생시킨다. 손으로 나열하지 않는다.

- 데스크탑: 우측 고정 목차, 현재 프로젝트 하이라이트(스크롤스파이)
- 모바일: 상단 고정 바 + 목차 토글

## 콘텐츠 분리

본문은 `content/cases.ts`, `content/projects.ts`에 타입과 함께 둔다.
컴포넌트에 문자열을 하드코딩하지 않는다.
어느 케이스가 어느 프로젝트에 붙는지는 `Project.caseIds`가 정한다.
내가 채우기 전까지 본문 필드는 빈 배열로 둔다.
